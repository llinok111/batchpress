# batchpress 使用说明（中文）

> 一句话定位：`sharp` 只会处理**一张图**，batchpress 负责把它变成**能中断、能续跑、不会重复干活的批处理**。

---

## 1. 安装

需要 Node.js ≥ 20.9（本机验证版本 v22.22.2）。

```bash
npm install
node bin/batchpress.mjs doctor     # 自检：Node / sharp / libvips / 磁盘余量
```

`doctor` 正常应输出：

```
node        v22.22.2
platform    win32 x64
free space  327 GB
presets     7
sharp       0.35.5 · libvips 8.18.7
```

---

## 2. 三分钟上手

```bash
# 1) 先看一眼：要处理多少文件、预计占多少磁盘（不写任何文件）
node bin/batchpress.mjs plan --in D:/photos --out D:/photos-webp --preset webp-q80

# 2) 正式跑
node bin/batchpress.mjs run --in D:/photos --out D:/photos-webp --preset webp-q80 --concurrency 4

# 3) 看结果
node bin/batchpress.mjs report --out D:/photos-webp --print
```

输出目录会**镜像输入目录结构**：`photos/a/b.jpg` → `photos-webp/a/b.webp`。

---

## 3. 日常运维四条命令

| 场景 | 命令 |
| --- | --- |
| 中途要停（可恢复） | `node bin/batchpress.mjs cancel --out D:/photos-webp` |
| 停了以后接着干 | `node bin/batchpress.mjs resume --out D:/photos-webp` |
| 看现在到哪一步 | `node bin/batchpress.mjs status --out D:/photos-webp` |
| 看哪些文件失败了 | 打开 `<out>/.batchpress/runs/<id>/failures.csv` |

`resume` 会**跳过已经完成的文件**，只做剩下的。已发布的结果文件不会被重新编码，也不会被覆盖。

---

## 4. 退出码（可以写进脚本判断）

| 码 | 含义 | 该做什么 |
| --- | --- | --- |
| 0 | 全部完成 | — |
| 1 | 参数错误 | 检查 `--in` / `--out` / `--preset` |
| 2 | 完成但有失败 | 看 `failures.csv`，多为坏图 |
| 3 | 被取消 | 直接 `resume` |
| 4 | 磁盘不足已暂停 | 腾空间后 `resume` |
| 5 | 找不到这次运行 | `--out` 指错了目录 |

```bash
node bin/batchpress.mjs run --in ./in --out ./out --quiet || {
  case $? in
    3) node bin/batchpress.mjs resume --out ./out ;;
    4) echo "磁盘不够，清理后重跑 resume" ;;
    2) echo "有坏文件，见 failures.csv" ;;
  esac
}
```

## 5. 常用预设

```bash
node bin/batchpress.mjs presets
```

- `webp-q80`（默认）：体积和兼容性平衡
- `jpeg-q82`：老系统/老浏览器都要能打开时用
- `avatar-256` / `thumb-128`：正方形裁剪，适合头像/缩略图
- `avif-q55`：体积最小，但慢 5–7 倍，适合归档而非批量回填
- `png-opt`：需要透明通道时用
- `reencode-jpeg`：统一格式并去掉 EXIF

**顺序保证**：先按 EXIF 方向转正 → 再裁剪/缩放 → 编码时剥离元数据。

## 6. 关键参数怎么定

| 参数 | 默认 | 什么时候改 |
| --- | --- | --- |
| `--concurrency` | 4 | 实测 4 是拐点：8 只快 0–3% 却多占 40% 内存，12 反而更慢。内存吃紧就降到 2 |
| `--attempts` | 2 | 磁盘/网络不稳可提到 3；坏图不会因为重试变好，重试只对"临时故障"生效 |
| `--reserve` | 512 MiB | 输出盘还放着别的东西时调大，避免把盘写满 |
| `--max-inflight` | 256 MiB | 单张图很大（>50 MB）时调大，否则会变成单线程 |
| `--timeout` | 120000 ms | 超大图/慢盘可调大 |

## 7. 状态存在哪、能不能删

```
<out>/.batchpress/runs/<runId>/journal.ndjson   ← 唯一的事实来源，别删
<out>/.batchpress/runs/<runId>/summary.json|md  ← 报告，可随时用 report 重新生成
<out>/.batchpress/runs/<runId>/staging/         ← 临时文件，正常结束为空
```

- `summary.*` 是**从 journal 推导**出来的，删掉后 `report` 一键重建。
- 删掉 `journal.ndjson` 等于丢失历史，但**已输出的图片不受影响**；再跑一次会因"文件已存在"而跳过。

## 8. 常见问题

**Q：第二次跑为什么 0 个任务？**
说明输出目录里已存在同名结果，默认跳过（这是幂等设计）。要强制重做加 `--overwrite`。

**Q：某个文件一直失败，一直重试很慢。**
坏图（截断/非图片/空文件）被归为不可重试，只会尝试一次，即使 `--attempts 5`。看 `failures.csv` 里的 code：`ECORRUPT`（损坏）、`EFORMAT`（不是图片）、`EEMPTY`（空文件）。

**Q：跑到一半断电了怎么办？**
直接 `resume`。进程被杀时正在处理的那一张会重做（约 1 次冗余），已发布的结果不会被重写。

**Q：能不能只处理一部分？**
`--limit 50` 只处理前 50 个（冒烟测试用）。要按规则筛选请先在文件系统层面挑目录。

**Q：GIF 动图变成单帧了。**
`sharp` 不支持写动画，这是上游限制，已在 README 的 Known limits 里注明。

## 9. 自证：怎么确认它真的没重复干活

```bash
node test/scaling.mjs 3        # 并发拐点（3 次取中位数）
node test/bench.mjs            # 各预设吞吐/内存
node test/drills.mjs           # kill -9 / 取消 / 磁盘闸门 演练
node test/verify-images.mjs    # 逐像素验证几何与方向
npm test                       # 53 个测试
```

`drills` 的真实输出示例（48 张图）：

```
kill -9 后 resume → done 48/48 · attempts 49（仅 1 次冗余）· staging 残留 0
取消后 resume    → 48/48 全部完成，已发布文件未重新编码
磁盘闸门         → 暂停瞬间写入 0 字节
```

完整数据见 `docs/RESULTS.md`。
